Por que precisamos de funções?

Veja o primeiro programa ao lado: o mesmo cálculo de média aparece três vezes. Se a regra mudar (por exemplo, a segunda prova passar a valer o dobro), teremos de corrigir três lugares e torcer para não esquecer nenhum.

Uma função é um bloco de código com nome. Escrevemos o bloco uma vez e o chamamos pelo nome sempre que precisarmos.

  • Reaproveitamento: escreve uma vez, usa muitas.
  • Organização: cada função resolve um pedaço do problema.
  • Correção: um erro corrigido na função fica corrigido em todos os usos.
Antes de executar, pergunte à turma: para trocar a regra da média, quantas linhas mudam em cada versão?

Definir não é executar

Quando o Python encontra um def, ele apenas guarda a função com aquele nome. O corpo só roda quando a função é chamada, e roda de novo a cada chamada.

Na chamada, a execução salta para dentro da função, executa o corpo e depois volta para a linha seguinte de quem chamou.

Por isso a função precisa ser definida antes da primeira chamada. A forma mais comum de organizar: todas as definições no topo do arquivo, o programa principal embaixo.

Peça para a turma prever a ordem das mensagens do primeiro exemplo antes de executar.

Parâmetros e argumentos

TermoOnde apareceExemplo
parâmetrona definição: é uma variável da funçãodef area(base, altura):

Na chamada, cada argumento é entregue ao parâmetro na mesma posição: o 1º argumento vai para o 1º parâmetro, e assim por diante. É como se o Python fizesse base = 3 e altura = 4 antes de começar o corpo.

O argumento pode ser qualquer expressão: um número, uma variável, uma conta ou até o resultado de outra função.

A quantidade de argumentos precisa bater com a de parâmetros. A última linha do exemplo passa só um. O que acontece?

Teste de mesa: o caminho de uma chamada

return: devolvendo um valor

return valor encerra a função e entrega o valor para quem chamou. A chamada passa a “valer” esse resultado, como len("abc") vale 3.

Com o valor em mãos, quem chamou decide o que fazer: guardar em uma variável, usar em uma conta, comparar em um if ou passar para outra função.

dobro(3) → 6dobro(3) + dobro(4) → 14dobro(dobro(2)) → 8
Na última linha do exemplo, a chamada de dentro é resolvida primeiro: dobro(2) vira 4, e então dobro(4) vira 8.

print ou return?

Esta é a confusão mais comum da aula. print mostra um valor na tela, para a pessoa. return devolve um valor para o programa, que pode continuar usando-o.

Mostra, mas não devolve

Devolve: quem chamou decide

Função sem return devolve None, o valor que representa “nada”. Regra prática: funções que calculam algo devem usar return; deixe o print para o programa principal, que decide como mostrar o resultado.

return encerra a função

Assim que um return é executado, a função termina na hora, mesmo que existam mais linhas depois dele ou que esteja no meio de um laço.

Isso permite escrever vários return, um para cada caso. Depois que um caso foi resolvido, não é preciso else: se a execução chegou à linha seguinte, é porque o return anterior não aconteceu.

Cuidado com caminhos sem return. Se nenhum caso for atendido e a função chegar ao fim, ela devolve None. Teste conceito(-1) e veja.

Funções que respondem sim ou não

Uma função pode devolver True ou False. Costumamos dar nomes que soam como pergunta: eh_par, eh_primo, tem_vogal. O return dentro do laço encerra a busca assim que a resposta é conhecida.

Quando a função devolve um bool, a chamada vai direto no if ou no while, e o código fica parecido com uma frase: if eh_par(n):.

Uma comparação já é True ou False. Por isso return n % 2 == 0 substitui um if inteiro.

Devolvendo mais de um valor

Um return só pode entregar um valor, mas esse valor pode ser uma tupla. Basta separar os resultados por vírgula: return a, b.

Quem chamou recebe a tupla e pode desempacotá-la em várias variáveis, como vimos na aula de coleções.

17 // 5 → 317 % 5 → 2q, r = (3, 2) → q = 3, r = 2
A função também pode receber uma lista e devolver um resumo dela. Os parâmetros e o retorno podem ser de qualquer tipo.

Variáveis locais

Variáveis criadas dentro de uma função, inclusive os parâmetros, são locais: nascem quando a função é chamada e desaparecem quando ela termina.

Fora da função, esses nomes não existem. A única forma de um resultado sair da função é pelo return.

Duas funções podem usar o mesmo nome de variável sem conflito: cada uma tem o seu próprio espaço de nomes, chamado escopo.

A última linha do primeiro exemplo tenta mostrar total fora da função. Peça para a turma prever o resultado.

Locais e globais

Variáveis criadas fora de qualquer função são globais. Quando uma função atribui um valor a um nome, ela cria uma variável local com esse nome, mesmo que exista uma global igual. A global não é alterada.

Uma função até consegue ler uma variável global, mas depender disso deixa o código difícil de entender: o resultado muda conforme coisas que estão fora da função.

E se a função atribuir a esse nome em qualquer ponto do corpo, o Python passa a considerá-lo local na função inteira. Usar antes de atribuir gera UnboundLocalError.

Boa prática: tudo o que a função precisa entra por parâmetro; tudo o que ela produz sai pelo return. (Existe a palavra global, mas evite-a.)

Listas como argumento

Lembra de “dois nomes, uma lista”? Passar uma lista para uma função funciona do mesmo jeito: o parâmetro vira outro nome para a mesma lista.

Por isso, se a função alterar a lista (append, lista[i] = ..., remove), a alteração aparece para quem chamou.

Com números, strings e tuplas isso não acontece: como são imutáveis, a função não tem como modificá-los.

Escolha de propósito: ou a função modifica a lista recebida e não devolve nada (como lista.sort()), ou cria uma lista nova e a devolve (como sorted(lista)).

Parâmetros com valor padrão

Um parâmetro pode ter um valor padrão, usado quando a chamada não envia aquele argumento: def saudar(nome, saudacao="Olá"):.

Você já usou isso sem perceber: round(x) arredonda para inteiro porque o número de casas tem padrão; print tem sep=" " e end="\n" como padrões.

round(2.567) → 3round(2.567, 2) → 2.57
Parâmetros com valor padrão vêm depois dos parâmetros obrigatórios. def f(a=1, b): é erro de sintaxe.

Argumentos nomeados

Na chamada, podemos dizer a qual parâmetro cada valor se destina: nome=valor. Assim a ordem deixa de importar e a chamada fica autoexplicativa.

É muito útil quando a função tem vários parâmetros com padrão e queremos mudar só um deles, por exemplo só o simbolo de linha.

Você também já viu isso: print(..., end="") e lista.sort(reverse=True).

Argumentos posicionais vêm primeiro e os nomeados depois: f(1, b=2) funciona, f(a=1, 2) não.

Funções chamando funções

Uma função pode chamar outras funções. Assim, um problema grande é quebrado em partes pequenas, cada uma fácil de escrever e de testar sozinha.

Durante a execução, o Python guarda uma pilha de chamadas: cada chamada em andamento fica empilhada sobre quem a chamou e, ao terminar, sai da pilha e devolve o resultado para quem está logo abaixo.

Uma função pode até chamar a si mesma. Esse é o tema da aula de Recursão, e a pilha de chamadas será a chave para entendê-la.

Organizando um programa

Um programa com funções costuma seguir este formato:

  1. Definições no topo, cada uma com um nome que diga o que ela faz (um verbo ajuda: calcular_, ler_, mostrar_).
  2. Um programa principal curto no final, que lê os dados, chama as funções e mostra os resultados.

A primeira linha do corpo pode ser um texto entre aspas triplas, a docstring, que documenta o que a função recebe e devolve.

Funções também evitam repetição de input: ler_opcao só devolve uma opção depois que ela for válida.

Módulos: funções prontas para importar

Um módulo é um arquivo com funções prontas. O Python traz vários; para usar, basta importar.

FormaComo chamar
import mathmath.sqrt(16)
from math import sqrtsqrt(16)
import randomrandom.randint(1, 6)
math.sqrt(16) → 4.0math.pi → 3.14159…random.randint(1, 6) → 1 a 6
Em um projeto real, as suas funções também podem ficar em um arquivo separado (por exemplo notas.py) e ser importadas em outros programas com import notas.
