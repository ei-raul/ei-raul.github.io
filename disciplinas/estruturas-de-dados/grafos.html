O que é um grafo?

Um grafo G = (V, E) é um conjunto de vértices (V, os objetos) ligados por arestas (E, as relações entre pares de objetos).

SituaçãoVérticesArestas
rede socialpessoasamizades ou “segue”
mapacidades, esquinasestradas, ruas (com distância)
cursodisciplinaspré-requisitos
internetpáginas, roteadoreslinks, cabos

Listas e árvores são casos particulares de grafos. A diferença é que, num grafo geral, qualquer vértice pode se ligar a qualquer outro, inclusive formando ciclos.

Três formas de guardar o mesmo grafo

O desenho é só para nós. O programa precisa de uma estrutura: matriz de adjacência, lista de adjacência ou lista de arestas. Clique em um vértice e compare.

Troque para dirigido: a matriz deixa de ser simétrica e cada aresta aparece só uma vez na lista. A lista de arestas é simplesmente [(0, 1), (0, 3), (1, 2), (4, 1), …].

Matriz de adjacência

Uma matriz V × V em que m[u][v] = 1 se existe a aresta u–v (ou o peso dela, num grafo ponderado), e 0 caso contrário.

  • Existe a aresta u–v? Basta olhar m[u][v]: O(1).
  • Quais os vizinhos de v? Percorre a linha toda: O(V), mesmo que v tenha 1 vizinho.
  • Memória: V² posições, sempre.

Num grafo não dirigido a matriz é simétrica: m[u][v] == m[v][u].

Lista de adjacência

Para cada vértice, uma lista só com os seus vizinhos. Em Python, um dict de listas (ou uma lista de listas, se os vértices forem 0, 1, …, V−1).

  • Vizinhos de v: direto, O(grau de v). É o que os percursos mais usam.
  • Existe u–v? Procura na lista de u: O(grau de u).
  • Memória: O(V + E).

Num grafo ponderado, cada vizinho vira um par (vizinho, peso).

A lista de arestas ([(u, v), …]) é o formato mais simples de ler da entrada e de ordenar por peso, mas responder “quem são os vizinhos de v” exige olhar todas as E arestas.

A maioria dos grafos reais é esparsa: cada vértice tem poucos vizinhos comparado com V. Uma rede com 1 milhão de pessoas e 100 amigos por pessoa teria uma matriz de 10¹² posições, quase todas zero.

Regra prática: lista de adjacência por padrão; matriz para grafos pequenos ou densos, ou quando a pergunta “existe u–v?” domina.

Lendo um grafo da entrada

Formato usado nos exercícios desta aula (e em maratonas de programação):

  • primeira linha: V E — número de vértices e de arestas;
  • depois, E linhas u v (ou u v peso);
  • os vértices são numerados de 0 a V − 1.

Como os vértices são números, uma lista de listas basta: g[u] é a lista de vizinhos de u.

Ordenar cada lista de vizinhos deixa a saída determinística: os percursos sempre visitam os vizinhos do menor para o maior. Os exercícios contam com isso.

Busca em largura (BFS)

A BFS explora o grafo em ondas: primeiro a origem, depois todos os vizinhos dela, depois os vizinhos dos vizinhos… Uma fila garante essa ordem.

Os números acima dos vértices são as distâncias em número de arestas a partir da origem. Troque a origem para 6 e preveja a ordem de visita antes de animar.

BFS em Python

  1. Coloque a origem na fila com distância 0.
  2. Enquanto a fila não estiver vazia, tire o primeiro vértice v.
  3. Para cada vizinho w ainda não descoberto: dist[w] = dist[v] + 1 e w entra no fim da fila.

Cada vértice entra na fila uma vez e cada aresta é olhada uma vez (duas, se não dirigido): O(V + E).

Use collections.deque: popleft() é O(1). Com uma list, pop(0) desloca todos os elementos (O(n)) e a BFS fica quadrática.

Teste de mesa da BFS

Acompanhe a fila e o dicionário dist. Repare que um vértice entra em dist no momento em que é descoberto, não quando sai da fila; por isso o 3 não entra duas vezes.

Busca em profundidade (DFS)

A DFS faz o contrário: segue um caminho o mais fundo possível e só volta (backtracking) quando não há vizinho novo. É o jeito de explorar um labirinto com a mão na parede.

Compare com a BFS a partir do mesmo vértice: os vértices visitados são os mesmos, a ordem e as arestas usadas mudam. Os números agora indicam a ordem de visita.

DFS recursiva e com pilha

A versão recursiva é a mais curta: visitar v é marcar v e chamar a DFS para cada vizinho não visitado. A pilha de chamadas do Python guarda o caminho de volta.

Em grafos grandes, a recursão pode estourar o limite do Python (cerca de 1000 chamadas). Aí trocamos a pilha de chamadas por uma pilha explícita (list com append/pop).

Componentes conexas

Um grafo pode estar dividido em “ilhas” sem ligação entre si: as componentes conexas.

Para encontrá-las, percorra a partir de cada vértice ainda não visitado. Cada novo percurso (BFS ou DFS, tanto faz) descobre uma componente inteira.

Apesar do laço sobre todos os vértices, cada vértice e cada aresta são tratados uma vez só no total: O(V + E).

Aplicações: grupos de amigos, regiões de uma imagem com a mesma cor (o “balde de tinta” dos editores), verificar se uma rede de computadores está toda ligada.

Detectando ciclos

Num grafo não dirigido, durante a DFS, encontrar um vizinho já visitado que não é o vértice de onde viemos significa que há dois caminhos até ele: existe um ciclo.

Por isso a pilha guarda pares (vértice, pai): a aresta de volta para o pai não conta como ciclo.

Uma árvore é justamente um grafo conexo sem ciclos. Ela tem sempre V − 1 arestas: uma a menos e ficaria desconexa, uma a mais e formaria um ciclo.

Em grafos dirigidos a regra muda (um vértice visitado por outro ramo não forma ciclo). Veremos um jeito simples de detectar ciclos dirigidos na ordenação topológica.

Menor caminho sem pesos

Na BFS, um vértice é descoberto pela primeira vez pelo caminho com menos arestas. Guardando quem descobriu cada vértice (o pai), dá para reconstruir esse caminho.

Para montar a rota até t, siga os pais de t até a origem e inverta a lista.

Funciona quando todas as arestas “custam” o mesmo: número de estações, de conexões entre pessoas, de cliques entre páginas.

Se o destino for encontrado, dá para parar a BFS ali mesmo (o break), pois a distância dele já é definitiva.

Labirintos: grafos implícitos

Nem sempre o grafo aparece como lista de arestas. Num mapa em grade, cada casa livre é um vértice e seus vizinhos são as casas livres acima, abaixo, à esquerda e à direita.

Não precisamos montar a lista de adjacência: calculamos os vizinhos na hora, somando os deslocamentos (±1, 0) e (0, ±1) e conferindo se a casa existe e não é parede.

A BFS a partir do início espalha as distâncias como uma mancha de tinta (flood fill). O mapa impresso mostra, em cada casa, quantos passos ela está do S.

Experimente abrir ou fechar paredes (#) no mapa e veja o número de passos até E mudar.

Arestas com peso: algoritmo de Dijkstra

Com pesos diferentes, o caminho com menos arestas pode não ser o mais curto. O Dijkstra sempre fixa o vértice pendente mais próximo da origem e tenta melhorar (relaxar) as distâncias dos vizinhos dele.

Repare no vértice 1: a aresta direta 0–1 custa 4, mas o caminho 0 → 2 → 1 custa 1 + 2 = 3. O Dijkstra descobre isso ao relaxar as arestas do 2.

Dijkstra em Python

  1. dist[s] = 0 e ∞ para os demais; a fila de prioridade começa com (0, s).
  2. Tire o par de menor distância (d, u). Se d for maior que dist[u], é uma entrada antiga: ignore.
  3. Para cada vizinho v com peso p: se dist[u] + p < dist[v], atualize e coloque (dist[v], v) na fila.

O heapq implementa a fila de prioridade (um heap, visto na aula de ordenação). Custo: O((V + E) log V).

O Dijkstra exige pesos não negativos. Com pesos negativos, uma distância “definitiva” poderia melhorar depois, e o algoritmo erra. Nesse caso usa-se Bellman-Ford.

Ordenação topológica

Em que ordem cursar disciplinas com pré-requisitos? Num grafo dirigido sem ciclos (DAG), uma ordem topológica coloca cada vértice depois de todos os que apontam para ele.

Algoritmo de Kahn: repetidamente retire um vértice com grau de entrada 0 e apague as setas que saem dele. Troque para o grafo com ciclo e veja onde o algoritmo trava.

Algoritmo de Kahn em Python

  1. Calcule o grau de entrada de cada vértice.
  2. Coloque os de grau 0 em prontos.
  3. Retire um pronto, acrescente-o à ordem e diminua o grau de entrada de cada vizinho; quem chegar a 0 fica pronto.
  4. Se a ordem terminar com menos de V vértices, há um ciclo.

Pode haver várias ordens válidas. Usar um heapq em prontos escolhe sempre o menor número, deixando a resposta única. Custo: O(V + E), ou O((V + E) log V) com o heap.

Outras aplicações: ordem de compilação de arquivos, instalação de pacotes com dependências, etapas de um projeto, células de uma planilha que dependem de outras.
