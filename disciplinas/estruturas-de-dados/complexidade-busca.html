Por que estudar estruturas de dados?

Uma estrutura de dados é uma forma de organizar dados na memória para que certas operações fiquem rápidas: buscar, inserir, remover, pegar o menor…

O exemplo ao lado faz as mesmas 100 consultas em uma lista e em um conjunto (set) com os mesmos 10 mil números. A resposta é igual; o tempo, não.

Não existe estrutura melhor em tudo. Cada uma acelera algumas operações e cobra em outras. Ao longo da disciplina, vamos aprender a medir esse custo e a escolher.

Vetor: elementos lado a lado na memória

Um vetor (array) guarda seus elementos em posições consecutivas da memória, todas do mesmo tamanho. Por isso o computador calcula o endereço de qualquer posição com uma única conta.

endereço(v[i]) = início + i × tamanho_do_elemento

Não importa se o vetor tem 6 ou 6 milhões de elementos: acessar v[i] custa sempre o mesmo. Dizemos que o acesso é O(1), tempo constante.

É também por isso que os índices começam em 0: o índice é o deslocamento a partir do início.

Em Python, a list é um vetor de referências: as posições consecutivas guardam endereços dos objetos. Os elementos podem ter tipos diferentes, mas o acesso por índice continua O(1). Em C, um int v[6] guarda os próprios números lado a lado.

Inserir e remover no meio custa caro

Como os elementos ficam colados, não há “espaço livre” entre eles. Para inserir no meio, é preciso deslocar todos os que vêm depois.

Inserir na posição p de um vetor com n elementos desloca n − p elementos. No pior caso (início), desloca todos: O(n).

No fim, não desloca nenhum: O(1). Remover segue a mesma lógica.

Vetor dinâmico: por que append é rápido

Um vetor de verdade tem tamanho fixo. A list do Python é um vetor dinâmico: reserva mais espaço (capacidade) do que usa (tamanho).

Quando enche, cria um vetor maior e copia tudo para lá. No código ao lado, o novo vetor tem o dobro da capacidade (o CPython cresce só cerca de 12,5% por vez; o que importa é crescer por um fator, não por uma quantidade fixa). Essa cópia é cara, O(n), mas acontece cada vez mais raramente.

Dobrando, a soma de todas as cópias fica abaixo de 2n: cada append custa em média menos de 2 cópias. Dizemos que é O(1) amortizado.

Experimente trocar o crescimento para self.capacidade + 1 (cresce de um em um) e compare o número de cópias.

Matrizes na memória

A memória é uma fila única de posições. Uma matriz L × C é guardada linha após linha: o elemento m[i][j] fica na posição i × C + j desse vetor.

Na matriz 3 × 4 acima, m[2][1] está na posição 2 × 4 + 1 = 9 da memória: antes dele há 2 linhas inteiras (8 elementos) e mais 1 elemento.

Assim, acessar m[i][j] também é O(1). Percorrer a matriz inteira visita L × C elementos: O(L·C), ou O(n²) se for quadrada.

Em C, int m[3][4] é exatamente isso: 12 inteiros seguidos. Em Python, uma lista de listas é um vetor de referências para as linhas.

Quanto custa um algoritmo?

Medir em segundos depende do computador, da linguagem e do que mais está rodando. Para comparar algoritmos, contamos quantas operações básicas eles fazem em função do tamanho da entrada, n.

Operação básica: uma comparação, uma soma, uma atribuição, um acesso a v[i]. Cada uma custa um tempo constante.

No exemplo, soma faz uma operação por elemento: n. pares compara cada elemento com todos: n × n.

Execute e observe a coluna pares: quando n aumenta 10 vezes, o trabalho aumenta quantas vezes?

Medindo o tempo de verdade

O tempo medido varia a cada execução, mas a proporção revela o comportamento: dobre n e veja quanto o tempo cresce.

Se o algoritmo é…dobrar n multiplica o tempo por
O(n)≈ 2
O(n²)≈ 4
O(n³)≈ 8
O(log n)quase nada (soma uma constante)

time.perf_counter() devolve um relógio de alta precisão, em segundos.

Como as funções crescem

Para n pequeno, quase tudo é rápido. A diferença aparece quando n cresce: a taxa de crescimento domina qualquer constante.

Com n = 100, um algoritmo exponencial levaria mais que a idade do universo. Com n = 1 milhão, um quadrático leva quase 3 horas e um O(n log n), menos de um segundo.

Notação O grande

Dizemos que um algoritmo é O(f(n)) quando, para n grande, ele faz no máximo algo proporcional a f(n) operações. É um limite superior do crescimento.

Como simplificar

  1. Ignore constantes multiplicativas: 3n + 5 → O(n).
  2. Fique só com o termo que cresce mais rápido: n² + 100n + 7 → O(n²).
  3. A base do logaritmo não importa: log₂ n e log₁₀ n diferem por uma constante → O(log n).
5n + 20 → O(n)n²/2 + n → O(n²)7 → O(1)n + log n → O(n)

Também existem Ω (limite inferior) e Θ (limite justo). Na prática, quando alguém diz “é O(n)”, quase sempre quer dizer “cresce linearmente”.

Melhor caso, pior caso e caso médio

O mesmo algoritmo pode trabalhar mais ou menos dependendo dos dados. Na busca sequencial em n elementos:

CasoQuando aconteceComparações

pioralvo no fim ou ausenten → O(n)

Normalmente analisamos o pior caso: é uma garantia. Se o pior caso é aceitável, qualquer entrada será.

Busca sequencial

A estratégia mais simples: olhar um elemento de cada vez, do início ao fim, até achar o alvo ou acabar o vetor. Funciona com qualquer vetor, ordenado ou não.

Convenção usada em toda a disciplina: a função devolve a posição do alvo, ou -1 se ele não estiver no vetor.

Custo: O(n) no pior caso. É o que o Python faz em x in lista e lista.index(x).

Mude o alvo na visualização para um valor que não está no vetor e conte as comparações.

Busca binária

Se o vetor está ordenado, dá para fazer como num dicionário de papel: abrir no meio e descartar a metade onde a palavra não pode estar.

  1. Mantenha o trecho ainda possível entre ini e fim.
  2. Olhe o elemento do meio.
  3. Se for o alvo, achou. Se for menor, o alvo está à direita: ini = meio + 1. Se for maior, está à esquerda: fim = meio - 1.
  4. Se ini passar de fim, o trecho ficou vazio: não está no vetor.

Cada comparação corta o trecho pela metade: no pior caso, O(log n) comparações.

Cuidados com a busca binária

Erros comuns

  • Vetor fora de ordem: o algoritmo não reclama, só devolve a resposta errada.
  • while ini < fim em vez de <=: deixa de olhar o trecho de um elemento só.
  • ini = meio em vez de meio + 1: pode ficar preso para sempre no mesmo trecho.

Pronto no Python: bisect

bisect_left(v, x) devolve a posição onde x está ou deveria ser inserido para manter a ordem. insort(v, x) insere mantendo a ordem (a busca é O(log n), mas a inserção ainda desloca: O(n)).

Desafio: raiz quadrada com busca binária

A busca binária não serve só para vetores. Ela funciona em qualquer intervalo onde a resposta “sim/não” muda uma única vez.

Encontre a raiz quadrada inteira de n: o maior r tal que r * r <= n. Não use math nem ** 0.5.

Para n = 1000000, a resposta é 1000. Quantos passos seu programa precisou? Compare com testar r = 0, 1, 2, … um por um.
